# D0-INF-01 — Manual First. Automated Second. Governed Always.
## BOSS Day Zero instructional doctrine · candidate v0.4

### Governing principle
**Manual First. Automated Second. Governed Always.** The learner understands a bounded operation before delegating its execution. Automation reproduces an examined procedure under explicitly specified permissions, exceptions, evidence requirements, and release controls. Governance is not an optional layer added after deployment.

### Manual First
The student works locally and deliberately. They identify source and destination, inspect the actual files, write a shared frame, move approved content across an explicit boundary, obtain a receipt, reconcile the destination against source truth, and document failure. The teaching objective is procedural comprehension and judgment. Manually performed steps do not imply secure or flawless operations by default.

### Automated Second
Once a process is describable and repeatable, translate it into a workflow specification with inputs, transformation steps, approvals, error branches, outputs, telemetry, and acceptance tests. Day One introduces Windmill as a possible executor; the earlier IPOS diagnostic should provide the initial requirements. The automated representation must undergo independent authorization, implementation testing, and security review; a good worksheet is not proof of a working workflow.

### Governed Always
Across both manual and automated modes, separate source authority, permitted action, technical capability, observed execution, correctness, and release approval. All boundaries must have transparent failure conditions. Any missing evidence creates UNKNOWN or NOT ESTABLISHED. Escalate to qualified specialists when data sensitivity, public exposure, irreversible actions, legal concerns, safety implications, or implementation complexity exceed the operator's competence.

### Relationship to the Information Supply Chain
The learner packages information with a manifest, selects the intended destination, inspects its condition and permissions, moves only what is allowed, and establishes a verified receipt. This is a teaching model—not a literal statement that text messages satisfy physical shipping controls. Transfer success is neither a guarantee of truth nor an authorization to publish.

### Assessment standard
A learner passes the Day Zero exercise only when they can: define bounded inputs and outputs; identify permissions; reproduce the manual transfer; produce source-linked evidence; name discrepancies; document recovery; and explain how the same operation would be represented in a candidate automated workflow. A verified learner lab is not professional certification or authorization for production security work.

### Later deployment
Self-hosted infrastructure offers an optional destination for qualified implementation, not a Day Zero dependency. Windmill, Docker containers, MCP interfaces, and databases may form a future control layer, subject to hosting capability, security, backups, operational cost, and accountable release review. External model APIs are optional dependencies whose contracts and limitations remain distinct from the operator's authority.

### Release status
Doctrine candidate for explicit human review. No claims of completed VPS deployment, NotebookLM media, verified Assignment 06 enforcement, or learner effectiveness are established by this text.

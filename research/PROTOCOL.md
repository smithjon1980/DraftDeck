# Candidate protocol development outline

Revision 0.1, 2026-10-09. Proposed; not frozen, preregistered or executed.

## Scope
First paper: governed AI-assisted document handoff reliability. Classroom learning and production Windmill automation require separate evaluation. Day Zero begins with manual local-device handoffs.

## Architecture to reconcile
Describe admission, execution, output adjudication and authorized release while preserving PRIME. Human accountability may be implemented through bounded prior authority; do not require approval on every output. The inspected Day Zero architecture is candidate, so reconcile higher doctrine before study freeze.

## Comparisons
Communication pilot: record plus optional commentary; same record without commentary; strict JSON, with shared semantic checks. Governance study: baseline versus BOSS under the same output contract and equivalent requirements, permissions, tools and receiver checks. Neither comparison establishes the other effect.

## Initial demonstrations
Specify a versioned source, request, expected output and receiver checks for:
1. Accepted handoff: supplied facts preserved and destination independently inspected.
2. Rejected handoff: missing required input or unsupported completion; dependent action blocked and rejection recorded.
These are feasibility demonstrations, not evidence of superiority.

## Extend fixtures
Include unavailable destination, partial transfer, interrupted recovery, capability without permission, evaluation pass without release authority, and correctly completed low-consequence work under prior authorization. Measure unnecessary holds and correct completion as well as unsupported claims.

## Before collection
Fix exact source commits; complete message schema and receiver implementation; define reference outputs, scoring rubric, run count, randomization, model/settings, failure handling and analysis accounting for dependence. Preserve raw responses, destination inspection, receiver decisions, repairs and interventions. Record privacy handling and rater disagreement procedures.

## Evidence required
Run ID; fixture/version; condition; model/settings; prompt; raw responses; tool/receiver records; destination artifact; claim-time evidence; scoring; authorization scope; timings; failure and repair history. No fabricated placeholder results.

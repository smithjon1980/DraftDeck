# Module 01 Instructor Guide and Key

**Version:** v1.0 candidate assessment package.
**Status:** Proposed pilot instruments; no learner outcomes or validated cut scores are claimed.

## Administration
Confirm the learner's phase: supported practice or independent demonstration.
Use the learner document's Guided learning opening only in supported teaching. Its question/case/definition/pressure-test/standard/worked-case/operator-move/boundary sequence follows BOSS Guided Reasoning Format (GRF-B dominant).
For independent demonstration, baseline and unseen transfer, omit that opening and any worked-case key. Give only the initial request, source packet, policy, response instructions and assessment conditions. Plain language and reader-facing prompts remain; explanatory hints do not.
Collect Stage 1 before revealing clarification. Record requested help and administration deviations.
Do not supply rubric answers as hints in independent demonstration.
Target 20–30 minutes for the main task plus explanation; this is a planning estimate, not a performance requirement. Adapt for access needs.

## Standardized clarification — R2
Provide after Stage 1 to every learner:
“The update is for OPERATIONS_LEAD in TRAINING_DRIVE, draft folder. Use the current facts in S1. Make a one-page update of no more than five bullets covering the delayed count, cause breakdown, next review and unknown recovery dates. Use APPROVED_LOCAL_RUNTIME only. Do not include contact details and do not change scheduling. Prepare only the update package now; put delay-process improvement in a separate proposed workstream. OPERATIONS_LEAD authorizes final release after source-faithfulness and coverage checks. Until then, any generated update is a draft candidate.”

This is a synthetic role, not a verified real recipient. It grants no actual external-service permission.

## Stage 1 acceptable reasoning
Known: one-page update requested; bundled improvement mission; S1 current/internal; S2 superseded; S3 restricted/unnecessary; fastest external service is ineligible.
Unknown: receiver, location, intended coverage/acceptance, release conditions.
HOLD the update execution while required conditions are unresolved.
REFUSE the forbidden transfer to EXTERNAL_AI_SERVICE under P1.
A package draft is permitted; source transmission and final production are not.
Do not require a specific phrasing if action scope and rationale are correct.

Useful questions establish destination, output purpose/coverage, boundaries of the improvement request and review/release authority. Several requirements may be resolved in one clear question.

## Stage 2 adequate package
Locally assigned package identity/version.
Purpose: factual current-delay update for OPERATIONS_LEAD.
Scope: package for one-page, at-most-five-bullet update only.
Inputs: S1 v2 with R1, R2 and P1 as governing requirements. S2 is provenance evidence for exclusion, not factual input to the update. S3 is unnecessary and excluded.
Handling: INTERNAL, APPROVED_LOCAL_RUNTIME only.
Destination: OPERATIONS_LEAD; TRAINING_DRIVE draft folder.
Admission: ACCEPT for the bounded clarified package under the simulation. This is entry permission, not final-output release.
Excluded: contact data, stale facts, external processing, scheduling changes, broad process redesign, wider sharing and actual execution during assessment.
Acceptance:
- one page, at most five bullets;
- count four; breakdown three supplier/one scheduling;
- Friday identified as next review, not recovery;
- recovery dates explicitly NOT ESTABLISHED;
- no invented dates, contacts or unsupported causal explanation;
- required coverage checked against S1 and R2;
- output identity/version and target location checked;
- OPERATIONS_LEAD release after required evidence.
Evidence is planned, not fabricated.

## Decomposition
The learner should flag “fix delay handling” as too broad for the update package.
A bounded first improvement package could inventory current delay-handling steps, but required inputs, scope, destination and acceptance must be aligned before execution. Do not score an invented improvement plan as established.
The destination's factual information need stays intact when unnecessary input material is removed.

## Candidate vignette key
One-page/open checks establish format/accessibility properties only.
S1 establishes next review Friday and unknown recovery dates.
“All four recover Friday” is unsupported. REVISE the candidate; hold its release pending correction and source-faithfulness verification. REJECT with a reasoned correction route is also defensible.
No universal human-review requirement is inferred; this particular fixture explicitly assigns OPERATIONS_LEAD release authority.

## Remediation
C1/C2/C6: distinguish mission, bounded update and separate workstream.
C3/C7: annotate current/stale/unnecessary sources.
C4: practice targeted clarification.
C5: rewrite vague “looks good” criteria as observable checks.
G1: match classification to eligible environments.
G2: distinguish generation, evidence, candidate disposition and release.

After practice, use unseen alternate material for an independent reassessment. Record the assistance level and form; do not reuse a memorized key as novel evidence.

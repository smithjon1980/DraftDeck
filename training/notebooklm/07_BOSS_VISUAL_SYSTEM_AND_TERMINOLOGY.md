# 07 — BOSS Visual System & Terminology (Shared Standard)

**Document role:** Standing reference for all modules: canonical vocabulary and visual identity. Applies to every generated artifact in every module.

---

## 1. Canonical Identity

- **BOSS — Bioscillate Operating System by Seven** — the governing system. Bioscillate: B-I-O-S-C-I-L-L-A-T-E. Public domain: www.bioscillate.com.
- **Bioscillate Logistics Framework** — the governing conceptual model.
- **PARCELS** — the seven-layer structural architecture.
- **Bioscillate PRIME Protocol** (short: PRIME Protocol; PRIME always uppercase) — the governed movement protocol.
- **DraftDeck** — a product implementing the production specialization. Never a synonym for BOSS.

> **BOSS owns the doctrine. DraftDeck implements a production specialization of that doctrine.**

## 2. Core Glossary (Operator Terms)

**PACKAGE** — a bounded unit of operational work with identity, contents, scope, destination, inputs, and acceptance condition. *Not equivalent to:* mission, prompt, conversation, output.

**MISSION** — the destination; what the sender ultimately wants to arrive. *Not equivalent to:* package, task, curriculum.

**MANIFEST** — the bounded list of packages in a block: identifiers, destinations, routes, handling constraints, verification requirements, status. *Not equivalent to:* to-do list (a manifest is bounded before movement begins).

**BLOCK** — a bounded operating window; the unit of operational commitment. *Not equivalent to:* package (the unit of accountability).

**ROUTE** — the handling path and destination decision for a package. *Not equivalent to:* movement (routing is a decision; movement is execution).

**HANDLER** — who or what performs a role on a package. *Not equivalent to:* model (a model is one capability provider behind a handler).

**COURIER / AGENT** — transports or transforms a package under declared instructions.

**FREIGHT / MODEL SERVICE** — computational capability used during transport or handling.

**SENDER** — originates a package or request. **RECEIVER / CONSIGNEE** — intended recipient and release context.

**SHIPPING LABEL** — machine-readable declaration attached before routing: identity, type, provenance, constraints, handling requirements. *Not equivalent to:* verification tag (which records what actually happened).

**VERIFICATION TAG** — proof-of-delivery metadata: RUN_ID, CARGO_CLASS, QUALIFICATION_ID, ROUTE_PLAN_ID, STATUS, ELAPSED_TIME. Controlled STATUS values: HELD / VERIFIED / RELEASED / BLOCKED.

**PROOF OF DELIVERY** — evidence that the correct cargo reached the correct destination in acceptable state. Produced by verification; never declared by the label.

**CONTROL DESK (Shipping & Receiving)** — human command, handling, and release authority.

## 3. Prohibited Vocabulary (Hard Rule)

Never use aviation-domain terminology, aviation-control imagery, or travel-through-meaning-space metaphors in any artifact, and never use predecessor product names tied to that theme. The full banned-term list is enforced by the repository ontology guard.

## 4. Visual Identity (from doctrine/composition-standard.md)

- **Canvas:** exact 16:9, default 1920×1080 (decks); infographics additionally in 1:1 square and portrait orientations.
- **Ground:** pure white #FFFFFF only. No alternate grounds in the core standard.
- **Ink:** near-black #1A1A1A.
- **Accent:** burnt orange #B34700 — restricted use (status, key marks, controlled emphasis) only.
- **Technical substrate:** drafting gray #DEDEDE for grid/construction lines.
- **Typography:** Georgia heavy serif titles · Courier New uppercase monospace kickers/metadata · Arial body.
- **Strokes:** 1.0pt frames/dividers · 0.5pt controls/connectors · 0.25pt grid/hatch/detail.
- **Prohibited treatments:** solid pictogram fills, UI red, gradients, glows, glossy 3D, soft pill shapes. State via hatching and line texture, not color alone.
- **Drafting aesthetic:** the system should read as engineered technical documentation, not marketing collateral.

## 5. Language Register

Operator-training voice: direct, concrete, procedural. Sentences describe actions, states, and decisions. Rules appear as short bolded statements. Questions that drive decisions appear as quoted prompts (e.g., "What exactly is being moved?").
